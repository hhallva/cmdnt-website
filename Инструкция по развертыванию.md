
# Локальная настройка
## 📋 Требования

- 💻 Windows 10/11 (Pro/Enterprise/Home с WSL2)
- 🐳 Docker Desktop с включённым **WSL2 бэкендом**
## Шаг 0: Подготовка

### 1. Проверить, что Docker работает

```powershell
docker --version
docker compose version
docker run --rm hello-world
```

### 2. Включи WSL2 (если ещё нет)

```powershell
# От администратора:
wsl --install
wsl --set-default-version 2
```

При необходимости перезагрузить ПК
## Шаг 1: Клонирование репозитория

```powershell
mkdir -p D:\Temp\Projects
cd D:\Temp\Projects

git clone https://github.com/hhallva/cmdnt-website.git
cd cmdnt-website
```

## Шаг 2: Настройка .env

```env
# === ОБЩИЕ ===
ASPNETCORE_ENVIRONMENT=Production или Development

# === MySQL ===
DB_HOST=db
DB_PORT=3306
DB_NAME=..
DB_USER=...
DB_PASSWORD=...
DB_ROOT_PASSWORD=..
DB_VOLUME_NAME=..

# === JWT ===
JWT_KEY=key_32_chars_min
  
# === Frontend ===
DOMAIN_NAME=yourdomain.local
VITE_API_URL=https://yourdomain.local

# === CORS ===
CORS_ORIGINS=https://yourdomain.local
FRONTEND_API_URL=https://yourdomain.local
```
JWT_KEY - необходимо придумать рандомную строку из 32 символов

## Шаг 3: Настройка локального домена
### 1. Добавление локального домена 
Необходимо открыть файл `hosts` находящийся в папке `C:\Windows\System32\drivers\etc\`
```powershell
notepad C:\Windows\System32\drivers\etc\hosts
```
### 2. Добавить строку в конец файла

```
127.0.0.1    ВАШ_ДОМЕН.local
```
### 3. Проверь, что домен резолвится

```powershell
ping ВАШ_ДОМЕН.local
```

## Шаг 4: Запуск контейнеров

```powershell
# В папке проекта:
docker compose up -d --build
```
Дождаться окончания загрузки

После завершения загрузки необходимо проверить что все контейнеры запущены при помощи команды `docker compose ps`

# На удалённом сервере

## Требования

- 🖥️ Linux-сервер (Ubuntu 22.04/24.04 LTS рекомендуется)
- 🔑 SSH-доступ с правами `root` или `sudo`
- 🌐 Зарегистрированный домен (например, `yourdomain.com`)
- 💾 Минимум 2 GB RAM, 20 GB диск

---

## Шаг 0: Подготовка сервера

### 1. Подключение к серверу

```bash
ssh root@YOUR_SERVER_IP
```

### 2. Обновление системы

```bash
apt update && apt upgrade -y
```

### 3. Установка базовых утилит

```bash
apt install -y curl git wget unzip nano
```

### 4. Настройка Firewall (UFW)

```bash
ufw allow OpenSSH
ufw allow 80/tcp
ufw allow 443/tcp
ufw enable
ufw status
```

### 5. Установка Docker

```bash
curl -fsSL https://get.docker.com | sh
```

Проверяем:

```bash
docker --version
docker compose version
```

### 6. Настройка DNS

У регистратора домена создай **A-запись**:

| Тип | Имя | Значение |
|-----|-----|----------|
| A | `@` | `YOUR_SERVER_IP` |
| A | `www` | `YOUR_SERVER_IP` |

Проверь, что домен резолвится:

```bash
ping yourdomain.com
```

> ⚠️ **Важно:** DNS должен указывать на сервер **до** запуска Caddy, иначе не выпустится SSL-сертификат от Let's Encrypt.

## Шаг 1: Клонирование репозитория

```bash
mkdir -p /opt/projects
cd /opt/projects

git clone https://github.com/hhallva/cmdnt-website.git
```

## Шаг 2: Настройка `.env`

```bash
nano .env
```

```env
# === ОБЩИЕ ===
ASPNETCORE_ENVIRONMENT=Production

# === MySQL ===
DB_HOST=db
DB_PORT=3306
DB_NAME=cmdnt_db
DB_USER=cmdnt_user
DB_PASSWORD=СЛОЖНЫЙ_ПАРОЛЬ_1
DB_ROOT_PASSWORD=СЛОЖНЫЙ_ПАРОЛЬ_2
DB_VOLUME_NAME=cmdnt_db_data

# === JWT ===
JWT_KEY=придумай_рандомную_строку_минимум_32_символа

# === Frontend ===
DOMAIN_NAME=yourdomain.com
VITE_API_URL=https://yourdomain.com

# === CORS ===
CORS_ORIGINS=https://yourdomain.com
FRONTEND_API_URL=https://yourdomain.com
```

> 💡 Сгенерировать случайный ключ можно так:
> ```bash
> openssl rand -base64 48
> ```

---

## Шаг 3: Настройка Caddyfile для продакшена

Открой `Caddyfile` (или создай, если его нет в корне проекта) и приведи к виду:

```Caddyfile
yourdomain.com {
    reverse_proxy frontend:80
}

api.yourdomain.com {
    reverse_proxy backend:8080
}
```

> ⚡ **Caddy автоматически:**
> - выпустит SSL-сертификат от **Let's Encrypt**
> - настроит редирект HTTP → HTTPS
> - будет обновлять сертификат сам
>
> Никаких ручных манипуляций с сертификатами! 🎉

Если API на том же домене — можно объединить:

```Caddyfile
yourdomain.com {
    handle /api/* {
        reverse_proxy backend:8080
    }
    handle {
        reverse_proxy frontend:80
    }
}
```

## Шаг 4: Запуск контейнеров

```bash
cd /opt/projects/cmdnt-website
docker compose up -d --build
```

Дождись окончания сборки, затем проверь статус:

```bash
docker compose ps
```

Все контейнеры должны быть в статусе `Up`.

Смотри логи, если что-то пошло не так:

```bash
docker compose logs -f
```

## Шаг 5: Проверка SSL-сертификата

Caddy выпускает сертификат автоматически. Проверить можно так:

```bash
# Статус сертификатов Caddy
docker compose exec caddy caddy list-modules

# Проверка снаружи
curl -I https://yourdomain.com
```

Должен вернуться `HTTP/2 200` и валидный сертификат.

Онлайн-проверка: [https://www.ssllabs.com/ssltest/](https://www.ssllabs.com/ssltest/)

## Шаг 6: Импорт данных в БД

### Вариант A — через phpMyAdmin (если доступен)

1. Открой `http://YOUR_SERVER_IP:8081`
2. Логин: `root`, пароль: из `.env` (`DB_ROOT_PASSWORD`)
3. Выбери БД → вкладка **"Импорт"** → загрузи `.sql` файл

> ⚠️ **Безопасность:** в продакшене не держи phpMyAdmin открытым наружу. Либо закрой порт `8081` в `docker-compose.yml`, либо ограничь доступ по IP через firewall:
> ```bash
> ufw delete allow 8081/tcp
> ```

### Вариант B — через консоль (рекомендуется)

Загрузи `.sql` файл на сервер:

```bash
scp dump.sql root@YOUR_SERVER_IP:/opt/projects/cmdnt-website/
```

На сервере выполни импорт:

```bash
docker compose exec -T db mysql -uroot -p"$DB_ROOT_PASSWORD" cmdnt_db < dump.sql
```

## Шаг 7: Автоматический перезапуск и мониторинг

### Перезапуск при перезагрузке сервера

Docker Compose по умолчанию не стартует сам. Создай systemd-сервис:

```bash
nano /etc/systemd/system/cmdnt-website.service
```

```ini
[Unit]
Description=CMDNT Website Docker Compose
Requires=docker.service
After=docker.service

[Service]
Type=oneshot
RemainAfterExit=yes
WorkingDirectory=/opt/projects/cmdnt-website
ExecStart=/usr/bin/docker compose up -d
ExecStop=/usr/bin/docker compose down
TimeoutStartSec=0

[Install]
WantedBy=multi-user.target
```

Активируй:

```bash
systemctl daemon-reload
systemctl enable cmdnt-website.service
systemctl start cmdnt-website.service
```

## Полезные команды

| Действие | Команда |
|----------|---------|
| Логи всех сервисов | `docker compose logs -f` |
| Логи конкретного сервиса | `docker compose logs -f backend` |
| Перезапуск | `docker compose restart` |
| Полная остановка | `docker compose down` |
| Остановка с удалением томов | `docker compose down -v` ⚠️ |
| Войти в контейнер | `docker compose exec backend sh` |
| Состояние БД | `docker compose exec db mysql -uroot -p -e "SHOW DATABASES;"` |
